# FitSquad 瘦身战队 · Agent 运营小队

一人公司运营手册：Agent 负责出草稿和给建议，人负责审核和执行。每天人工投入约 30 分钟。主体先用个体工商户。

> 本目录内容已与 `docs/01-PRD-MVP.md`（PRD v0.8）和 `docs/02-整体解决方案.md`（v0.8）对齐。两边冲突时以 PRD 为准。

## 分阶段启用

| 阶段 | 启用 Agent | 触发条件 |
|---|---|---|
| 种子期 | 内容官、数据官、风控官（3 个） | 上线即用 |
| 增长期 | + 活动官、用户运营官 | 注册用户 > 1000 |
| 企业期 | + 商务官 | 出现企业线索（第二阶段企业版） |

未启用的 Agent 文件保留在 `agents/` 备用，当天不运行。种子期的活动、触达、组队撮合由人直接在种子群里做，依据是数据官每天产出的「流失预警名单」（见 `agents/data.md`）。MVP 唯一核心假设是留存 + 自发裂变，所以种子期最重要的人工动作就是按名单捞人。

产品事实（详见 PRD v0.6）：
- 定位：熟人 / 同事（公司、部门、好友、家庭）3–10 人组队较劲的小游戏；瘾点是"我在这群人里排第几 + 有人在看我"。
- 战队：周期队伍自选 14/21/30/60 天；≥3 人且全员确认即开赛；48 小时截止时已确认 ≥3 人自动开赛（未确认者移出并退回押注），不足 3 人自动解散、押注退回；Day 1 = 开赛次日 00:00，Day 1 内须完成起始称重；开赛后不能加人；**每人同时只能参加 1 支战队**。
- 积分：只有一种——活力值（新人完善档案 1000、打卡、步数、邀请、结算所得），只用于押注与荣誉（徽章 / 称号，纯虚拟）。不可提现、不可转让，12 个月滚动有效。**MVP 没有积分商城、没有充值积分、没有实物出口。**
- 押注：每人 100/200/500/1000 活力值（全队统一，队长定），或 0 押注友谊赛（不进奖池、无系统奖励积分，只发徽章）。
- 个人目标按 kg 设定：下限 = max(0.5kg, 周数 × 0.25kg)，上限 = min(周数 × 1.0kg, 初始体重 × 8%, 初始体重 − 20 × 身高m²)；BMI < 18.5 不能设减重目标，未满 18 岁不能参加押注挑战。
- 结算（PRD 4.5，S = 押注，R = 14 天 100 / 21 天 150 / 30 天 200 / 60 天 400）：全员达成：退回 S + R + 0.5×S 全员加成 + "铁血战队"徽章；部分达成：达成者退回 S + min(奖池 ÷ 达成人数, 0.5×S) + 0.5×R，超上限部分系统回收；失败者打卡率 ≥80% 返还 0.3×S（坚持奖），其余进奖池；全员失败：打卡率 ≥80% 返还 0.3×S，其余系统回收；新用户（注册 <14 天或首次挑战）失败押注由系统回收。平台不抽成。
- 打卡：有效打卡日 = 称重 / 步数 ≥6000 / 饮食或运动打卡任一项；完整周称重至少 2 次，不足则该周有效打卡日最多计 5 天；打卡率 = 有效打卡日 / 挑战天数。终点称重窗口 T−48h ~ T+48h，需口令 + 3–5 秒现场短视频；质疑窗口 T+72h 关闭，质疑只转人工；有成员在人工审核时全队延后结算（≤ 72 小时，超时视为通过）。
- 过程积分：称重打卡 +5、步数 ≥8000 +5、连续 7 个有效打卡日 +30、邀请新人 +200（被邀请人完成首期挑战且打卡率 ≥50% 后发放，每月最多 10 人）；打卡积分每人每天只算一次。
- 留存三件套（PRD 4.14）：连胜 Streak（连续有效打卡日，首页主角数字；每满 7 天送 1 张免断卡、最多 2 张，断签自动顶上，只保护连胜数字不影响结算）、队伍连胜（全队当天都打卡才 +1，一人缺就清零）、每天一条社交钩子（被谁反超 / 谁 @你）、每晚 20:00 战况卡（一键转进战队群）、打卡后盲盒式可变奖励（纯虚拟，不发可押注积分）。段位 / 赛季 / 战队 PK 不做，留 V1.1。
- 补缝机制（PRD v0.7）：没队伍的人可以「先一个人热身」攒连胜（不押注、不进榜、不发打卡积分，入队后连胜带入）；首期默认友谊赛 · 21 天；最后 7 天可「预约下一期」，结算后预约 ≥3 人自动开组；部分达成 / 全员失败时结算页主按钮是「开复仇局」；分享卡落地页对已开赛战队显示「围观」（只看 %）+「报名下一期」。运营话术里可以直接引导用户用这些入口。
- 上手（v0.8）：登录只要微信授权，直接进首页；没有身体档案页，第一次设目标时填身高、体重 + 1 条参赛声明 + 健康数据单独同意；手机号在第一次押注时才授权；建队一屏全预填；邀请卡是“战书”（发起人 + 一句狠话）；打卡打开即相机。
- 提醒：订阅消息是一次性授权，靠"打卡后订阅明天的提醒"；催一下是分享卡片，不是订阅消息；超越提醒只做小程序内横幅 + 分享卡片，不发订阅消息。
- 互动与文案（PRD 4.7 / 4.8 / 4.13，v0.8 减法）：周称号 4 个（卷王 / 打卡钉子户 / 嘴硬王者 / 摸鱼选手）、表情 3 个（💪 / 就这？ / 你礼貌吗）、催一下 = 今日战况卡（一张卡 @ 没打卡的人，转进战队群）、开赛前夜“猜猜谁先摸鱼”（第 7 天揭晓，猜中得「🔮 神预言」）、线下趣味惩罚（建队选填，不涉及积分）。语气诙谐搞怪、激发好胜心，只调侃行为不调侃身体。首页只有一个连胜数字（在队里 = 队伍连胜）。
- 站内不做健康知识文章；内容官只做站外增长内容。
- 目标用户 25–40 岁职场人群及亲友；种子期以同事 / 好友组队、验证留存与自发裂变为主。

### inbox 标准文件（所有 Agent 共用，按需读取）

## 每天约 30 分钟工作流

| 时间 | 步骤 | 动作 |
|---|---|---|
| 0–5 分 | 1. 导出 | 从后台导出前一日数据，脱敏后放入 `ops/inbox/YYYY-MM-DD/` |
| 5–10 分 | 2. 运行 | 按顺序运行已启用的 Agent：数据官 → 风控官 →（增长期起）用户运营官 → 活动官 → 内容官 →（企业期起）商务官（每周一、四跑）。种子期只跑 数据官 → 风控官 → 内容官。每个 Agent 以 `agents/<name>.md` 为系统提示词，读当日 inbox |
| 10–12 分 | 3. 产出 | Agent 将结果写入 `ops/drafts/YYYY-MM-DD/<agent>-<类型>.md` |
| 12–27 分 | 4. 审核 + 捞人 | 先看风控（涉及积分/账号的必须人工处理），再看数据日报里的「流失预警名单」并在种子群 / 私聊逐个跟进（种子期），最后看内容文案。按各文件"人工审核点"逐条勾选，不通过的直接删除或改写 |
| 27–30 分 | 5. 归档 | 通过的移入 `ops/published/YYYY-MM-DD/`，执行（发文、手动调整），在文件头补 `状态: 已执行 / 执行人 / 时间` |

运行顺序的原因：数据官的日报是其他 Agent 的输入，风控结论会影响当天触达（被标记的用户不触达、不推奖励）。

## 全员红线

1. 不做任何医疗宣称（不说"治疗""根治""药效""保证瘦 X 斤"），涉及健康的内容统一加"仅供参考，身体不适请就医"。
2. 绝不建议、暗示或设计提现、套现、积分转卖、线下交易；MVP 不存在积分商城和充值积分，不要提及"兑换"。
3. Agent 不直接改数据库、积分、账号状态，不封号，只输出建议，由人工执行。
4. 只读 `ops/inbox` 下的脱敏数据，不索取、不推断真实身份。
5. 不鼓励超出系统健康上限的减重目标，不鼓励节食、脱水、催吐等极端方式。
6. 文案红线（PRD 4.13）：只调侃行为（偷吃、摸鱼、熬夜、赖床、嘴硬、不打卡）；绝不调侃体型、体重数字、长相、性别、年龄、健康状况；失败不羞辱（自嘲 + 约复仇）；不出现"宁可挨饿也要瘦""不吃晚饭"这类说法；调侃是友好较劲，不是羞辱。
7. 活动奖励永不包含影响公平和结算的东西（补卡、免罚 / 免死金牌、改目标、额外称重机会）。
