# FitSquad 瘦身战队 · Agent 运营小队

一人公司运营手册：Agent 负责出草稿和给建议，人负责审核和执行。每天人工投入约 40 分钟（Agent 流程 30 分钟 + 商城发货 10 分钟）。主体先用个体工商户。

> 本目录内容已与 `docs/01-PRD-MVP.md`（PRD v0.3）和 `docs/02-整体解决方案.md`（v0.3）对齐。

## 分阶段启用

| 阶段 | 启用 Agent | 触发条件 |
|---|---|---|
| 种子期 | 内容官、数据官、风控官（3 个） | 上线即用 |
| 增长期 | + 活动官、用户运营官 | 注册用户 > 1000 |
| 企业期 | + 商务官 | 出现企业线索 |

未启用的 Agent 文件保留在 `agents/` 备用，当天不运行；种子期的活动、触达、组队撮合由人直接在种子群里做。

产品事实（详见 PRD v0.3）：
- 微信小程序；3–10 人组队（公司/家庭/好友）；周期队伍自选 14/21/30/60 天；≥3 人且全员确认即开赛；48 小时截止时已确认 ≥3 人自动开赛（未确认者移出并退回押注），不足 3 人自动解散、押注退回；Day 1 = 开赛次日 00:00，Day 1 内须完成起始称重；开赛后不能加人；每人最多同时参加 2 支战队。
- 积分两种：活力值（新人 1000、打卡、步数、邀请、结算所得，可押注、可兑换）；充值积分（V1.1，1 元 = 100，只能兑换商品/会员，不能押注、不能进奖池）。全部不可提现、不可转让，12 个月滚动有效。
- 押注：每人 100/200/500/1000 活力值（全队统一，队长定），或 0 押注友谊赛（不进奖池、无系统奖励积分，只发徽章）。
- 个人目标按 kg 设定：下限 = max(0.5kg, 周数 × 0.25kg)，上限 = min(周数 × 1.0kg, 初始体重 × 8%, 初始体重 − 20 × 身高m²)；BMI < 18.5 不能设减重目标，未满 18 岁不能参加押注挑战。
- 结算（PRD 4.5，S = 押注，R = 14 天 100 / 21 天 150 / 30 天 200 / 60 天 400）：全员达成：退回 S + R + 0.5×S 全员加成 + "铁血战队"徽章；部分达成：达成者退回 S + min(奖池 ÷ 达成人数, 0.5×S) + 0.5×R，超上限部分系统回收；失败者打卡率 ≥80% 返还 0.3×S（坚持奖），其余进奖池；全员失败：打卡率 ≥80% 返还 0.3×S，其余系统回收；新用户（注册 <14 天或首次挑战）失败押注由系统回收。平台不抽成。
- 打卡：有效打卡日 = 称重 / 步数 ≥6000 / 饮食或运动打卡任一项；称重每周至少 2 次；打卡率 = 有效打卡日 / 挑战天数。终点称重窗口 T−48h ~ T+48h，需口令 + 3–5 秒现场短视频；质疑窗口 T+72h 关闭，质疑只转人工。
- 过程积分：称重打卡 +5、步数 ≥8000 +5、阅读健康知识 +1、连续 7 个有效打卡日 +30、邀请新人 +200（被邀请人完成首期挑战且打卡率 ≥50% 后发放，每月最多 10 人）；打卡积分每天只算一次，不按战队重复；重叠战队中 R 较低那支的系统奖励部分按 50% 发放。有成员在人工审核时全队延后结算（≤ 72 小时，超时视为通过）；当周称重不足 2 次，该周有效打卡日最多计 5 天。
- 提醒：订阅消息是一次性授权，靠"打卡后订阅明天的提醒"；催一下是分享卡片，不是订阅消息；超越提醒只做小程序内横幅 + 分享卡片，不发订阅消息。
- 积分商城（V1.0，PRD 4.12）：只用可用活力值兑换（冻结中不可用）；虚拟装扮 100–500 即时到账；运动好物 1,000–9,900（体脂秤每月限量 5 台），需收货地址、7 天内人工发货、每人每月最多 2 件、注册满 30 天且完成过 ≥ 1 期挑战；兑换后不退不换，质量问题换货；流水类型 `redeem`（取消退回 `redeem_refund`）。商城永不卖补卡、免罚、改目标、额外称重机会。
- 互动与文案（PRD 4.7 / 4.8 / 4.13）：周称号（卷王 / 打卡钉子户 / 步数刺客 / 气氛组组长 / 嘴硬王者 / 摸鱼选手）、调侃表情（就这？/ 我先瘦为敬 / 你礼貌吗）、线下趣味惩罚（建队选填，不涉及积分）。语气诙谐搞怪、激发好胜心，只调侃行为不调侃身体。
- 目标用户 25–40 岁职场人群及亲友；前期以拉新为主。

### inbox 标准文件（所有 Agent 共用，按需读取）

路径：`ops/inbox/YYYY-MM-DD/`

| 文件 | 格式 | 关键字段 |
|---|---|---|
| `users.csv` | CSV, UTF-8 | uid(哈希), reg_date, channel, invite_uid, gender, age_band, credit_score, last_active |
| `teams.csv` | CSV | team_id, type(company/family/friend), size, cycle_days, stake, start_date, end_date, status(forming/active/settling/settled/dissolved) |
| `checkins.csv` | CSV | uid, team_id, date, type(weigh/life/steps/start/end), weight_kg, steps, has_photo, has_video, photo_hash, code_used, device_hash, doubt_count, doubt_reason, review_status |
| `points_ledger.csv` | CSV | uid, date, point_type(vitality/recharge), type(init/stake/settle/reward/recharge/redeem/redeem_refund/reclaim/expire), amount, balance |
| `orders.csv` | CSV | order_id, uid, product_id, category(virtual/goods), price, status(待发货/已发货/已完成/已取消), created_at, shipped_at（不含收货地址、电话；发货时在后台直接看） |
| `funnel.csv` | CSV | date, visit, register, create_team, join_team, team_started, d7, d14, d30, share |
| `feedback.md` | Markdown | 客服/群聊/反馈原文摘录，已去除姓名手机号 |
| `bd_leads.csv` | CSV | lead_id, org_type, size_band, source, stage, note（无联系方式）|

脱敏要求：不放手机号、真实姓名、微信号、openid 明文；uid 用哈希；体重只保留到 0.1kg。

## 每天约 40 分钟工作流（Agent 30 分钟 + 商城发货 10 分钟）

| 时间 | 步骤 | 动作 |
|---|---|---|
| 0–5 分 | 1. 导出 | 从后台导出前一日数据，脱敏后放入 `ops/inbox/YYYY-MM-DD/` |
| 5–10 分 | 2. 运行 | 按顺序运行已启用的 Agent：数据官 → 风控官 →（增长期起）用户运营官 → 活动官 → 内容官 →（企业期起）商务官（每周一、四跑）。种子期只跑 数据官 → 风控官 → 内容官。每个 Agent 以 `agents/<name>.md` 为系统提示词，读当日 inbox |
| 10–12 分 | 3. 产出 | Agent 将结果写入 `ops/drafts/YYYY-MM-DD/<agent>-<类型>.md` |
| 12–27 分 | 4. 审核 | 先看风控（涉及积分/账号的必须人工处理），再看数据日报，最后看内容/活动/触达文案。按各文件"人工审核点"逐条勾选，不通过的直接删除或改写 |
| 27–30 分 | 5. 归档 | 通过的移入 `ops/published/YYYY-MM-DD/`，执行（发文、建活动、手动调整），在文件头补 `状态: 已执行 / 执行人 / 时间` |
| 30–40 分 | 6. 商城发货 | 人工处理（不经 Agent）：打开后台发货队列 → 先看风控报告里被标记的订单（多账号集中兑换先暂停）→ 打包下单寄出 → 回填快递单号转"已发货"；检查创建超过 5 天仍未发货的订单，确保 7 天内发出；处理换货申请（仅质量问题）；库存 ≤ 2 时补货或下架。无待发货订单时跳过 |

运行顺序的原因：数据官的日报是其他 Agent 的输入，风控结论会影响当天活动和触达（被标记的用户不触达、不推奖励）。

## 全员红线

1. 不做任何医疗宣称（不说"治疗""根治""药效""保证瘦 X 斤"），健康内容统一加"仅供参考，身体不适请就医"。
2. 绝不建议、暗示或设计提现、套现、积分转卖、线下交易。
3. Agent 不直接改数据库、积分、账号状态，不封号，只输出建议，由人工执行。
4. 只读 `ops/inbox` 下的脱敏数据，不索取、不推断真实身份。
5. 不鼓励超出系统健康上限的减重目标，不鼓励节食、脱水、催吐等极端方式。
6. 文案红线（PRD 4.13）：只调侃行为（偷吃、摸鱼、熬夜、赖床、嘴硬、不打卡）；绝不调侃体型、体重数字、长相、性别、年龄、健康状况；失败不羞辱（自嘲 + 约复仇）；不出现"宁可挨饿也要瘦""不吃晚饭"这类说法；调侃是友好较劲，不是羞辱。
7. 商城和活动奖励永不包含影响公平和结算的东西（补卡、免罚 / 免死金牌、改目标、额外称重机会）。

| Agent | 文件 | 启用阶段 | 核心职责 | 主 KPI | 频率 | 主要产出 |
|---|---|---|---|---|---|---|
| 内容官 | `agents/content.md` | 种子期 | 健康小知识、公众号/朋友圈/社群文案、分享卡 / 海报 / 周称号 / 超越提醒 / 商城调侃文案（按文案红线） | 分享率、分享带来的注册数 | 每日 | `content-daily.md` |
| 数据官 | `agents/data.md` | 种子期 | 漏斗日报、周报、PRD 第 9 节核心指标预警、积分负债跟踪 | 报表准时率、异常预警及时性 | 每日 + 每周 | `data-daily.md` |

| 活动官 | `agents/event.md` | 用户 > 1000 | 设计战队挑战赛、节点活动、中期加码 | 成团率、全员达成率 | 每周 + 节点 | `event-plan.md` |

| 商务官 | `agents/bd.md` | 有企业线索后 | 企业团建/HR 福利合作、商城供货、异业合作方案 | 企业线索数、企业开团数 | 每周 2 次 | `bd-pipeline.md` |
