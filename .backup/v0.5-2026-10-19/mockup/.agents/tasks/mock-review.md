## High-level view

结算三页的数字已经和规格一致。09-success 明细是退回 200 + 系统奖励 200 + 全员加成 100 = 500；09-partial 是退回 200 + 奖池分成 100 + 系统奖励 100 = 400，奖池行写明「上限 0.5 × 押注 = 100；超出 40 系统回收」；09-fail 中 Lily 拿回 60，大刘变体为 0。三页都有「人工审核中」切换态，文案统一，也写明全队一起结算。04-step2、05、02a、02c、03-home 和 14b 里的结算摘要也都按 500 / 400 改过，部分达成者的旧数字已全部清除。

目标规则在 06 和 04-step3 用同一套口径，下限 1.1kg（-1.5%）、上限 4.3kg（-6.0%），公式推导数字都对（5.8kg、10.8kg）。滑杆位置和 JS 的回弹逻辑与上下限一致。04-step2 加了 0 押注选项，带「0 = 友谊赛」标签、解释文案和 toast。48h 自动开赛规则同时出现在 04-step2 的提示条、05 的契约条款和倒计时卡里。

隐私规则在 07 落地正确：只有小王那行显示 kg（带 🔒），队友只显示 % 和目标 %。「催一下」现在弹出分享卡片面板，注明不消耗订阅消息额度。FAB 的避让留白（104px）足够让排行最后一行和页尾滚出按钮。08 三页都有称重标准和「有效打卡日 = 任一项」；end 页有 3–5 秒短视频卡和 48h 窗口提示。02b 有单独的健康数据同意、隐私政策链接和不适宜人群勾选（含切换态）。11 页拆分了活力值和充值积分，写明 12 个月有效，通篇没有积分变现类字样。10 页战队榜按平均 % 降序排列，达成率只作副信息。

问题集中在跨页的「时间线」：同一个余额或战队成绩，在进行中页面和已结算页面上被同时使用；另外还有 05 押注计数、08-daily 口令要求、08-end 流程跳转三处小的不一致。

### 余额时间线：同一个数被当成两个时间点的值

```
11-points（进行中, 鹅厂第 9 天）  总 1,658 / 冻结 200 (12-05 鹅厂押注)
09-partial（鹅厂结算后）          当前积分 1,658   ← +400 后应变化
10 好友榜（大刘 "本期 -0.6%"）    大刘 1,050 = 09-fail 大刘结算后余额
10 战队榜「本月结算」              鹅厂 -3.8% = 结算后平均, 但 07 仍在第 9/30 天
```

这几个数都是 SHARED-SPEC §5/§6 直接规定的，所以这不是页面执行出错，而是规格自身的逻辑漏洞（confirmed）。用户点进结算页再回积分中心，会看到 +400 之后余额没变。按「不重新设计」的约束，这里只标记，不改；需要在 spec 里定好以后再统一改页面。

### 05 契约页的押注计数（likely）

契约条款写「当前押注 600 积分（3/5 人）」，成员区却是阿杰 ✓、小王 ✓、Lily「设定中」。06 的按钮是「确定目标，冻结 200 积分」，也就是押注在确认目标时才冻结，所以 Lily 还没押。按新的 48h 规则，「已确认人数」决定能不能自动开赛，这个计数在 v0.2 里比以前更重要。05 本轮改动过，但没有 git 历史，判断不了这个数是不是这一轮引入的。

### 07 战队主页布局

FAB 底边离手机底部 100px，tabbar 高 86px，所以 FAB 覆盖 screen 底部往上 14–62px 这一段；`has-fab` 留了 104px，截图也确认大刘那行在 FAB 上方。初始视图里 FAB 压住了「战队动态」标题右侧的「🔒 队友间只显示百分比」，要滚动才能看到。小王那行 meta 文案约 180px 宽，而 flex 列只有约 129px（343 减去名次、头像、走势图、打卡状态和间距），截图里确实折成了两行（confirmed）。这一行变高后，排行下方那句「大刘今天还没打卡…」离 FAB 顶边只剩几个像素；以后排行区再加高一点，初始视图里就会被按钮盖住。
